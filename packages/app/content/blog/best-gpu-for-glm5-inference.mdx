GLM-5 is a large model with limited GPU coverage in our benchmark suite so far. Only 3 GPUs and 1 framework (sglang) are tested, but the results already show a clear hierarchy. We benchmarked it on [InferenceX](https://inferencex.semianalysis.com); for a model with broader coverage, see our [DeepSeek-R1-0528 benchmarks](/blog/best-gpu-for-dsr1-inference). Note: InferenceX support for this model is still early; expect more GPUs and frameworks in future updates.

## Key Findings

- NVIDIA B200 on FP8 with sglang hits **1,673.6 tok/s/GPU**, the fastest config for GLM-5.
- B200 on FP4 reaches 1,187.2 tok/s/GPU, 29% behind the FP8 result on the same GPU.
- NVIDIA H200 on FP8 gets 639.5 tok/s/GPU, 62% slower than B200.
- AMD MI355X on FP8 manages only 420.5 tok/s/GPU, the slowest of the three GPUs tested.

## Which GPU should you pick for GLM-5?

B200 on FP8 with sglang is the only competitive option right now at 1,673.6 tok/s/GPU. TTFT is 526.6ms, TPOT is 83.7ms. H200 can run it, but 46,130.9ms TTFT at its top-throughput config makes it impractical for interactive use. MI355X on FP8 gets 420.5 tok/s/GPU with a 162.5ms TPOT, which is too slow for most production workloads. Wait for more framework support before deploying on non-B200 hardware.

## FP8 vs FP4 on GLM-5

On B200, FP8 (1,673.6 tok/s/GPU) beats FP4 (1,187.2 tok/s/GPU) by 41%. This is unusual. On most models, lower precision wins on throughput. FP4 does have better TPOT (58.8ms vs 83.7ms), so the FP8 advantage comes from higher concurrency (128 vs 64). Only B200 has both precisions available; the other GPUs are FP8-only.

## NVIDIA B200 vs NVIDIA H200 on GLM-5

B200 is 2.6x faster on throughput: 1,673.6 vs 639.5 tok/s/GPU. H200's TTFT of 46,130.9ms at its best-throughput config is a dealbreaker for latency-sensitive workloads. B200 delivers 526.6ms TTFT. TPOT is close (83.7ms vs 62.9ms), so H200 isn't inherently slower on per-token generation. The gap is in how well it handles batching.

## Fastest time to first token

NVIDIA B200 on FP8 with sglang at concurrency 128: 526.6ms TTFT. B200 on FP4 is slightly slower at 605.6ms. AMD MI355X comes in at 1,368.1ms. H200's best TTFT is 46,130.9ms at its highest-throughput config, which isn't comparable (different concurrency). With only sglang available, there's no framework tuning to improve these numbers yet.
