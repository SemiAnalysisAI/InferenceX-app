AMD MI355X on mori-sglang FP4 with disaggregated prefill jumped from 1,893 to 4,223 tok/s/GPU on DeepSeek-R1-0528 inference, a 2.2x improvement in 10 days. The gain came from expanded concurrency sweep configs and an updated FP4 image.

## Before/After

|                        |      Before |       After | Change |
| ---------------------- | ----------: | ----------: | -----: |
| Throughput/GPU (tok/s) |       1,893 |       4,223 |  +123% |
| Median TTFT (ms)       |      29,501 |      71,289 |      - |
| Median TPOT (ms)       |        17.1 |       108.1 |      - |
| Framework              | mori-sglang | mori-sglang |      - |
| Concurrency            |         256 |       2,048 |      - |
| Date                   |  2026-03-03 |  2026-03-13 |      - |

Latency went up because the after config runs at 8x the concurrency (2,048 vs 256). At that batch size, throughput is what matters.

The mori-sglang FP4 disagg line shows a sudden jump on March 13. Other MI355X configs stayed flat or grew gradually. The atom FP4 line (3,652 tok/s) was the previous AMD best; mori-sglang FP4 disagg now beats it by 16%.

## What Changed

[PR #899](https://github.com/SemiAnalysisAI/InferenceX/pull/899) added more sweep configs for MI355X FP4 disagg and bumped the FP4 image to the Feb 27 latest build. The wider concurrency sweep (up to 2,048) found a config that trades latency for throughput, and the updated image contributed its own gains.

## Competitive Context

Before this update, the best MI355X result on DeepSeek-R1 was 3,652 tok/s/GPU (atom FP4). Now mori-sglang FP4 disagg hits 4,223 tok/s/GPU, the top AMD config. That's still 77% behind the NVIDIA GB300 at 18,132 tok/s/GPU. At $0.10/Mtok vs the GB300's $0.04/Mtok, the MI355X costs 2.4x more per token on this model.
