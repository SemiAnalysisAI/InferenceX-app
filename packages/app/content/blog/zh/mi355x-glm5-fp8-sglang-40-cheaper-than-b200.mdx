GLM-5 发布 14 周后，在 8k/1k 工作负载下，AMD MI355X SGLang FP8 在双方共有的单节点运行区间内，大部分交互性水平上的每百万 token 成本低于 NVIDIA B200 SGLang FP8。使用 MTP 时，插值得到的最大成本降幅约为 **29.6%，出现在约 24.3 tok/s/user**（B200 $0.3388/M，MI355X $0.2384/M；B200 / MI355X 成本比为 1.421 倍）。不使用 MTP 时，最大降幅约为 **23.7%，出现在约 11.2 tok/s/user**（$0.3161/M vs $0.2411/M；成本比为 1.311 倍）。双方均使用 **SGLang v0.5.12** 和 FP8 KV 缓存。本次比较采用截至 2026-05-20 的历史数据快照。

这正是关键的节奏。GLM-5 发布后，一个季度内 AMD 就完成了上游 SGLang kernel 的合入（[sgl-project/sglang PR #21511](https://github.com/sgl-project/sglang/pull/21511)）及其他优化，并提交了配套的 InferenceX 方案（[InferenceX PR #1440](https://github.com/SemiAnalysisAI/InferenceX/pull/1440)），将该模型的 FP8 单节点成本曲线翻转为 AMD 占优。速度就是护城河。

GLM-5 是智谱（ZAI）的 MoE 旗舰模型，于 2026-02-11 发布 — 距本文采用的快照约 14 周。该模型拥有 **744B 参数的稀疏 MoE 架构，每 token 激活约 40B**：256 个专家采用 top-8 路由（约 5.9% 稀疏度），外加共享专家。公开的架构名称为 `glm_moe_dsa` — 模型在解码路径中集成了 **DeepSeek 稀疏注意力（DSA）**，这与 DeepSeek 在 V3.2 中引入的稀疏注意力模式相同，也是 SGLang 的 TileLang 后端所围绕构建的核心，同时采用多头潜在注意力（MLA）进行 KV 缓存压缩以支持其 200K 上下文窗口。

在 MI355X 上，等效能力在四月中旬通过 SGLang 的 TileLang 后端落地，由此带来的解码吞吐量提升使得 MI355X 较低的单 GPU TCO（$1.48/GPU/hr，B200 为 $1.95/GPU/hr，数据来源 [SemiAnalysis AI Cloud TCO 模型](https://newsletter.semianalysis.com/p/ai-cloud-economics)）得以转化为真正的每 token 成本优势，而非被软件差距所淹没。

## 推动这一结果的关键优化

AMD 方面的标志性性能优化之一是 [sgl-project/sglang PR #21511](https://github.com/sgl-project/sglang/pull/21511)（由 [HaiShaw](https://github.com/HaiShaw) 提交，2026-04-03 合入）。该 PR 通过 SGLang 的 TileLang 后端为 MI300/MI355 启用了 FP8 KV 缓存和 FP8 注意力 kernel（在 DeepSeek-V3.2 和 GLM-5 上均已测试），并针对不同硬件代际采用了不同的融合策略：

- **在 MI355 上**，该 PR **复用了现有的 `fused_qk_rope_cat_and_cache_mla` kernel 来同时处理 Q 和 KV 的 FP8 量化**。QK rope 拼接、MLA 缓存写入以及 Q 和 KV 的 FP8 量化全部合并到每个解码步骤的单次 kernel 调用中 — 无需额外的 HBM 往返，无需单独的量化 kernel 启动。

TileLang 依赖版本已更新以在 AMD 上启用 FP8 GEMM，并新增了 `sparse_mla_fwd_decode_partial_fp8` kernel 用于部分解码归约路径。该 PR 报告 MI355 吞吐量提升超过 5%（MI300 超过 10%），gsm8k 准确率无下降（DeepSeek-V3.2 0.945 → 0.946；GLM-5 0.946 → 0.950），通过 `--kv-cache-dtype fp8_e4m3` 配合 TileLang 预填充/解码后端激活。

## 基准测试数据

更正（2026-10-25）：此前版本将成本降幅误写为 40%，且部分比较超出了双方共有的实测区间。本文标题、开篇结论和下表均基于同一批历史测量数据，按仪表板当前的插值方法重新计算。

## 等交互性成本对比

对每种硬件与 MTP 设置，在其吞吐量 Pareto 前沿上使用与仪表板相同的单调三次 Hermite 样条插值，再按 `TCO_$/GPU/hr × 1e6 / (3600 × interpolated throughput)` 推导成本。MI355X MTP 将 TP=4 与 TP=8 数据点合并为一条前沿。成本比和降幅均使用未舍入的成本计算：`saving = 1 − MI355X cost / B200 cost`。

双方共有的实测交互性范围约为：使用 MTP 时 18.052–90.435 tok/s/user，不使用 MTP 时 10.722–42.032 tok/s/user。MTP 在 18 tok/s/user 或非 MTP 在 10 tok/s/user 的比较均需要外推，因此不报告这两个比较。MTP 的最大插值降幅出现在约 24.32 tok/s/user，表中采用 24.3。MI355X MTP 在约 89.13 tok/s/user 的交点之前成本更低，此后 B200 更低；90 tok/s/user 行的负降幅表示这一反转。

## MI355X 在 GLM-5 上的后续展望

此次结果为单节点、聚合、仅 FP8。仍有两个差距待弥合：

- **FP4 可组合性。** 本次对比中 B200 使用的是 CUDA nightly 上的 FP8。B200 NVFP4 SGLang 的 GLM-5 方案已开始交付，将进一步压缩 B200 的成本曲线。MI355X MXFP4 GLM-5.1 SGLang 已通过 [InferenceX PR #1098](https://github.com/SemiAnalysisAI/InferenceX/pull/1098) 于 2026-04-21 交付，但 MI355X 上的 FP4 + MTP 组合尚未达到本文展示的 FP8 + MTP 方案的水平。
- **分离式部署和宽专家并行。** MI355X 上的 GLM-5 尚无分离式部署或宽 EP 方案。NVIDIA 的 GB200 NVL72 Dynamo TRT-LLM 和 Dynamo vLLM 方案在 Kimi K2.5 上已展示了[机架级宽 EP 带来的约 3 倍每 GPU 吞吐量优势](https://inferencex.semianalysis.com/zh/blog/gb200-nvl72-kimi-k2-5-vllm-wide-ep-3x-vs-b200)。AMD 尚未为 GLM-5 交付分离式部署方案。
