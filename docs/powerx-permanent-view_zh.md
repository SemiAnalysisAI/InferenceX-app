# 现有 Dashboard 中的 PowerX 图表

[English](./powerx-permanent-view.md)

PowerX 扩展 `/inference` 中已有的 **Measured Power / Measured Energy** 和 `/gpu-metrics` 页面，继续使用现有功能开关。目标是直接从 Dashboard 截图表达文章中的比较，并通过分享链接恢复所选数据和图表。应用中不新增文章专页，也不内嵌冻结的文章数据集。

## 文章图表对应关系

| 比较内容                                                   | 现有 Dashboard 中的入口                                                                              |
| ---------------------------------------------------------- | ---------------------------------------------------------------------------------------------------- |
| H200 实测与配置功耗、能耗的差距                            | 实测功耗或能耗 → 对比 → 功耗口径；同图显示四种口径，并排显示功率与能耗                               |
| B200/MI355X、B200/B300、GB200/GB300 在相同服务速度下的比较 | 沿用硬件筛选和 Interactivity、TTFT、E2E 横轴；单指标图使用原有 Perf Ruler，多曲线图使用图内 ISO 标记 |
| Prefill 与 decode 的功率、阶段能耗                         | 对比 → 预填充与解码；阶段能耗保留各自的 input/output token 分母                                      |
| 完整请求的能耗分解及 prefill 占比                          | 对比 → 请求能耗分解；先并排显示阶段功耗与占比，下方显示统一 output token 分母的能耗贡献              |
| 硬件功耗、输出和能耗的相对变化                             | 对比 → 硬件相对变化；选择基准及对比配置/运行，使用相同服务水平横轴，不按并发配对                     |
| GB200/GB300 正式服务窗口内的功耗变化                       | GPU Metrics → 服务窗口功耗；选择运行、产物和窗口，再选择第二个运行                                   |

原有单指标图保留统计范围、平均值/P75/P90、TDP 百分比和能耗分母/单位。切换到配置功耗后再返回，会恢复之前的实测设置。

多次运行均值和 min/max 区间需要明确的重复运行集合；最新的一条结果不能标为 N=3 均值。额外分析中的回归拟合图不在本次交付范围内。

## 数据路径

Benchmark 与采集器 → 结果及 power-audit 产物 → 现有入库流程 → Neon → 现有 benchmark API → 共享数据变换 → 实测功耗/能耗图。

时间序列从现有 GPU Metrics API 的 `power-audit` 来源读取，保留产物身份、manifest、原始样本、服务窗口及验证信息，在浏览器内完成绘图变换。

对比图沿用工作负载、精度、日期/运行、硬件和非官方运行筛选。它使用当前 Y 指标覆盖筛选之前的数据，避免缺少实测值时同时隐藏有效的配置功耗点。缺失值保留断点，不填零。连线仅连接同一配置、日期和来源运行的相邻观测点，并明确标注其不是 Pareto 前沿。ISO 标记只在有效相邻点之间线性插值，不外推，也不替用户选择存在歧义的重复 X 值。单指标 Perf Ruler 继续读取原生图表的实际曲线。

单指标功率图沿用已有 Measured Power 的交互：**Optimal Only（仅最优）** 开启时只显示边界点，关闭时显示全部点，曲线、坐标范围、缩放和标尺保持不变。实测、机箱估算及设施额定/估算功率在两种图表布局和非官方运行叠加中遵循同一规则。恒定的额定或估算功率保留实际测试的横轴范围；能耗图继续使用较低能耗的 Pareto 前沿。

## 四种功耗口径

| 口径       | 功率                              | 每成功输出 token 的能耗                               |
| ---------- | --------------------------------- | ----------------------------------------------------- |
| GPU 实测   | Producer 的 GPU 板卡实测功率      | 同窗口积分得到的 GPU 能量 / 成功输出 token 数         |
| GPU 额定   | 硬件注册表中的 TDP                | TDP / 按全部已分配 GPU 归一化的输出吞吐量             |
| 全设施配置 | 硬件注册表中每 GPU 的设施配置功率 | 配置功率 / 按全部已分配 GPU 归一化的输出吞吐量        |
| 全设施估算 | 现有系统功耗模型，计入一次 PUE    | GPU 实测 J/output-token × 设施估算功率 / GPU 实测功率 |

TDP、运行时设置的功率上限和实测功率是不同概念。估算功率沿用共享模型明确验证过的历史单节点功率契约；估算能耗仍要求 schema-2 同窗口证据。各面板会标出缺失的数据覆盖情况。设施功耗仍为估算值，沿用已有模型版本、机箱和校准覆盖范围及 CPU/DRAM/PUE 假设；不支持的硬件或工作负载不会借用其他模型。固定序列分离式部署的吞吐量需从 decode GPU 分母换算为全部 GPU；AgentX 已使用全部 GPU。

阶段能耗重构要求经过验证的 schema-2 分离式部署数据及有效的汇总、阶段能耗。汇总 J/input 与 J/output 使用相同能量分子，两者的比值可恢复实际成功 input/output token 比例。先用该比例将 prefill J/input 换算为 J/output，再与 decode 相加。缺少任何角色或分母时，不显示重构总量或占比；不假设固定的 8:1 请求长度比例。

## 服务窗口时间序列

`/api/gpu-metrics?runId=…&source=power-audit` 读取已有 `power_audit_*` 产物。历史链接受 GitHub 保留期限制，需建立持久归档才能作为永久发布证据；默认的原始 GPU 指标 API 和视图继续可用。

设备以主机和设备编号共同标识，角色来自 manifest。样本必须覆盖正式窗口端点及预期设备。在每个 GPU 上按准确端点裁剪、插值和积分，并与通过验证的能量核对后再汇总角色。缺少设备、角色不一致、窗口无效或采样覆盖不足时显示不可用，不绘制不完整的池功耗。

每个面板从各自窗口的零点开始，显示池 GPU 数量、时长、平均功率、采样最大值及产物来源。两个面板使用相同功率刻度，prefill 为虚线，decode 为实线。TDP 参考线取自当前硬件注册表，并与实测功率或历史运行功率上限区分。采样最大值不能证明采样间隔内的瞬时峰值。

## 分享、刷新与截图

- 推理分享状态使用 `i_mcompare` 保存对比方式，`i_mstat` 保存横轴统计量，`i_iso` 与 `i_iso_axis` 保存目标及实际横轴字段（例如 `mean_intvty`），`i_mbase` / `i_mcomp` 保存相对比较的配置、日期、运行及叠加来源。目标缺少匹配的坐标轴签名时不恢复。原生标尺继续使用带坐标轴签名的 `i_rulers`。
- GPU Metrics 分享链接保存来源视图、两个运行 ID、产物名称、不可变的 `gm_artifactId` / `gm_compareArtifactId` 及窗口标识。固定产物或窗口缺失时显示不可用，不自动替换为其他数据。链接不包含凭据或遥测数据本身。
- 最新实测视图在重新获得焦点及页面可见时每五分钟刷新可用性和活动查询。明确选择的运行、日期及历史比较保持固定。采集、入库和 API 缓存发布是独立环节。
- 文章长期使用的链接应先固定 **Run Date（运行日期）**，再选择相对比较来源并分享。Latest 链接会跟随最新数据集合；已保存的精确来源在刷新后缺失时显示不可用，不自动替换。
- 图中明确标注统计量和测量口径，区分模型估算、阶段能耗重构及 ISO 插值。
- 精确复现文章数值需要相同运行、统计量、固定功率参考和多次运行汇总规则。当前数据支持相同图表能力，但不自动代表相同实验集合或结论。

## 验收

定向单元及浏览器测试覆盖功耗公式、分离式部署归一化、缺失/无效输入、阶段能耗重构、时间序列积分、插值范围、筛选与运行叠加、分享恢复及桌面/移动布局。交付截图前，真实产物需复现已知的窗口时长、角色均值和采样峰值。继续使用现有功能开关，不新增部署或发布路径。

相对比较保留各配置和运行的独立身份，先在相同 X 值处分别插值，再计算百分比。功耗和输出使用 `(对比值 − 基准值) / 基准值`，能耗降低使用 `(基准值 − 对比值) / 基准值`。派生比较取两个来源测试 X 值的并集及所选 ISO 目标，仅使用覆盖重叠区间；缺失值和有歧义的重复 X 值保留断点。截图和 CSV 保留来源身份及变化方向。
