# Huawei copy-bandwidth evidence

The added static series are Ascend950PR_9579 (28 Cube, 56 Vector, 128 GiB) and Ascend910B3 on Atlas 800T A2 (20 Cube, 40 Vector, 64 GiB). No power-limited A3 data is included. Neither series changes the global GPU specification catalog or inference-data normalization.

`huawei-bandwidth.json` preserves all 42/41 full-precision plotted points, source input hashes, per-process medians, observed p10/p90 ranges, pool geometry and sample counts. Each size has three processes × six blocks × twenty observations. Aggregation is the pooled median amortized time, converted by `2 * message bytes / time`; bounds invert p90/p10 latency and are not confidence intervals. No observations are smoothed or supplied for missing sizes. Source files are the validated October 7 rotating-pool 950PR experiment and October 13 A2 comparison; the initial scratch-fill curves and overlap-rejected runs are excluded.

Both experiments use FP16 `copy_` operations in complete rotating-pool NPU graph replays. Each direction has at least 512 MiB and two slots. Every block is checked against source bits before and after timing. The time is amortized over a complete rotation, not an isolated-copy latency. Unlike the GPU series, it is not `triton.testing.do_bench` on one FP32 buffer pair. The UI states this above the chart and labels Huawei tooltip times as amortized. No physical HBM-traffic counters prove that every access misses cache.

The 950PR endpoint is about 1,447 GB/s at 16 GiB. The 910B3 endpoint is 1,271.519 GB/s at 8 GiB; 16 GiB is absent because two source and two destination slots would occupy all 64 GiB before runtime overhead. Both MBU curves use 1,600 GB/s. The 950PR figure is an assumed nominal reference, and the 910B3 figure is corroborated by the [OEM 910B3/2 brochure](https://www.yingjiangdata.com/UpLoad/202601/2026013061541417.pdf#page=15) and [CANN memory example](https://www.hiascend.com/document/detail/zh/CANNCommunityEdition/800alpha002/devguide/opdevg/ascendcbestP/atlas_ascendc_best_practices_10_0036.html). Neither exact board ceiling was independently measured.

UI/API coverage: the existing bandwidth/MBU/latency selector is presentation-only. Both hardware keys are available through `test=mem-bw`, `gpu=<key>` and `gpu=all`; `test=all` returns empty sections for tests unavailable on an explicitly selected device. API rows retain optional uncertainty/pool fields, `metadata.protocol`, `dtype`, CANN/torch_npu versions and `missingSizesBytes`. `peakBandwidthSource` states the per-run reference qualification. The dashboard and API share `transformUbenchxRun`.
