# Ascend scalar-controller memory profiles

The `core-memory-profiles` view preserves the four 128 MiB matrices from the 6–7 October 2026 (Singapore time) Cube/Vector locality rerun: 28 Cube scalar controllers and 56 Vector scalar controllers, each tested with one active core and with concurrent launches. Both core types use identical scalar pointer-chase instructions on the same allocation. Each address is averaged over six passes before computing the mean absolute difference between two cores' address profiles.

The data file contains every displayed matrix entry without rounding, the actual physical core-ID lists, the original pair statistics and source hashes. The arrays preserve ID gaps. Runtime-ID die groups divide IDs below 54 from those at or above 54; they do not assign physical coordinates. The frontend and API recompute within/between-group means from unique off-diagonal pairs using the same pure function. A shared 0–113.63708496093749 SYS_CNT-tick color domain applies to all four panels.

The unit is raw `SYS_CNT ticks`, not `clock64` cycles or nanoseconds. These are profile differences, not direct core-to-core latency, cache-controller distance or a recovered floorplan. The 128 MiB pattern is separate from the smaller-footprint profile classes and independent contention experiments; those extra inferences are not added here. Concurrent launches lack a grid-wide start barrier, and their fine structure is less repeatable than the broad grouping. No cache-sharing claim follows solely from these positive distances.

The complete displayed data is in `ascend-core-profiles.json`. Its `sourceSha256` identifies the original plotted-data JSON; each panel also retains the hashes of its archived analysis inputs. This publication contains the displayed matrices and aggregate statistics, not every original per-load observation.

Coverage: `/ubenchx/core-memory-profiles` and its `/zh` sibling show all four panels. Hover, keyboard arrows and pinning only inspect already-returned cells; they do not change data. The hub's new test is available through `/api/v1/views/ubenchx?test=core-memory-profiles`, with `gpu=all` or `gpu=Ascend 950PR_9579`, and as `coreMemoryProfiles` in `test=all`. Explicit device selections leave other unavailable test sections empty. API `unit`, `metric`, `limitations`, `coreIds`, `dieGroups` and `colorLimits` preserve the measurement interpretation.
